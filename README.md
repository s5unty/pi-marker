# pi-marker

Pi 原位荧光笔插件：打开标记模式后，用鼠标拖选已经完成的 AI 回答，松开后留下黄色背景，可以连续标记多处。重新拖选碰到已有高亮时，实时擦除相交部分，未选中的高亮保持不变。
标记保存在会话中，不改写回答，不进入模型上下文。支持将当前分支的全部高亮导出为 **Markdown 文件或剪贴板内容**。

**实验版，支持 `@earendil-works/pi-coding-agent` / `pi-tui` 1.5.2 和 1.6.0 的 Fullscreen 模式。**

这是纯插件，不需要修改或重新编译 Pi 核心。它确实依赖少量 **私有运行时接口**，不是官方稳定的标注 API：未验证的 Pi 版本会拒绝安装这些钩子，不能假定升级后可直接使用。

精确版本检查是本插件针对私有接口采取的保护措施，**不是 Pi 对所有插件的要求**。开发依赖固定版本以便复现测试，`peerDependencies` 保持 `"*"`，运行时再检查已验证版本及接口形状；不是通过 npm 强制宿主降级。

`0.2.3` 支持 Pi 1.6.0：兼容新的 `childLines` 布局缓存和只读渲染数组，同时保留 1.5.2 的 `mouseLayout` 适配。会话高亮格式不变，旧记录无需迁移；已加入由 1.5.2 实际生成的锚点恢复回归测试。也适配 **pi-tidy 0.11.1** 新增的段间空行、边框留白和代码按钮偏移；以实际布局坐标定位，不猜测固定边框高度，已通过其 `frame`、`rail`、`rules`、`off` 四种布局的真实 CLI 测试。

`0.2.2` 将命令统一为 `/marker`，不再注册旧前缀；已有高亮记录无需迁移。

`0.2.1` 将剪贴板导出简化为 `copy` 子命令，文件导出使用 `export [路径]`。

`0.2.0` 新增 Markdown 导出：只保留高亮片段及其格式，按原文顺序排列，合并重叠标记。

`0.1.1` 修复了与 **pi-tidy 0.9.8** 的布局兼容问题：支持其回答边框、侧边线、分隔线及折叠后的可见回答。读取实际呈现树，通过 Markdown 组件身份和逐行字素校验定位，不在整个聊天记录中搜索相似文字。pi-tidy 的呈现接口同样是私有接口，其他版本/美化插件仍需验证。

## 快速试用

从 GitHub 安装插件，然后启动 Fullscreen 模式：

```bash
pi install git:github.com/s5unty/pi-marker
pi --tui-mode fullscreen
```

等待一条回答完成，然后输入：

```text
/marker on
```

使用正常的鼠标左键拖选。选区与已有高亮**完全不重叠**时，松开后留下黄色高亮；只要选区**碰到已有高亮**，本次就仅擦除交集，选区内原本没高亮的文字不会被上色，选区外的高亮保持不变。

擦除在拖动过程中实时预览，恢复原始文字样式；向回缩小选区时，不再选中的部分恢复原高亮。松手后才统一保存，整次操作可用 `/marker undo` 撤销；拖动中按 `Esc` 取消。**不要按住 Shift**：有些终端会用 Shift 绕过应用鼠标处理，改用终端原生选区。

安装后，恢复最近会话时会自动加载本插件：

```bash
pi -c --tui-mode fullscreen
```

恢复时自动显示已有高亮，但笔的模式默认是 `off`，避免误标。关闭插件不会删除会话里的标记；再次加载插件时恢复显示。

`pi install` 会将插件登记到个人配置 `~/.pi/agent/settings.json`，之后启动时自动加载，无需修改 Pi 核心或再使用 `-e`。如果之前通过 `-e` 或本地包路径加载，请移除旧的加载方式，避免重复加载同一个插件。

## 命令

| 命令 | 功能 |
| --- | --- |
| `/marker` | 切换标记模式开/关 |
| `/marker on` | 打开黄色荧光笔 |
| `/marker off` | 关闭笔，保留高亮，恢复普通选择和复制 |
| `/marker erase` | 仅擦除模式：实时擦除与选区相交的部分，保留同一笔中未选中的片段，不新增高亮 |
| `/marker undo` | 撤销上一次添加、擦除或清除；重启后仍可撤销 |
| `/marker clear` | 确认后清除当前分支的全部标记，可撤销 |
| `/marker status` | 查看模式、笔数、已识别文本块、pi-tidy 布局数及标记匹配情况 |
| `/marker text <唯一片段>` | 键盘替代操作：标记最近一条已完成回答中的唯一片段；在擦除模式下则擦除 |
| `/marker export` | 在当前工作目录创建一个唯一命名的 Markdown 摘录文件 |
| `/marker export <路径>` | 导出到指定文件；支持带空格的路径，不覆盖已有文件 |
| `/marker copy` | 将相同的 Markdown 内容复制到剪贴板 |
| `/marker help` | 简短帮助 |

`text` 命令不需要引号。匹配忽略空白，遇到重复片段会拒绝猜测，请提供更长的片段或使用鼠标。这个命令不会调用模型。为保留键盘命令原有语义，`text` 在 `on`/`off` 模式下仍是新增高亮，只有在 `erase` 模式下才局部擦除；鼠标的“有重叠就擦除”规则不用于键盘命令。

底部状态示例：`marker:mark · 2笔`。`marker:off` 表示只是显示已有标记，普通选中不会新增标记。标记/擦除模式下的拖选不会自动复制到剪贴板；`off` 后恢复原来的 `fullscreenCopyOnSelect` 行为。

## 导出 Markdown

```text
/marker export
/marker export highlights.md
/marker export "notes/my highlights.md"
/marker copy
```

- 导出的是**当前会话分支的全部已保存高亮**，不是仅屏幕上可见的部分，也不是终端的临时选区。笔处于 `off` 时也可导出；仍需 Fullscreen 模式。
- 按回答、内容块及文字位置排序，重复/重叠/相邻范围合并；不连续片段用 Markdown 分隔线隔开，避免误以为原文相连。
- 保留粗体、斜体、删除线、链接目标、标题级别、列表/任务项、引用、行内代码和代码块语言。不会为了补齐格式而把未选中的段落、列表正文或代码语句一起导出。
- 只选中代码的一部分时，自动补齐安全的代码围栏；不复制代码块的可选标题。引用链接转为独立可用的内联链接，省略未选中的可选链接标题。
- 普通表格可保留选中单元格中的内容和格式，未选中单元格留空，不补入未选中的列标题。发生跨列换行/纵向重排的表格不猜测位置。公式仅在完整选中且可安全还原时导出。
- 这是保留样式的 Markdown 摘录，不是源文件的逐字节切片；必要时补齐语法、转义字面符号。界面边框、复制按钮等装饰不作为正文导出。
- 默认文件名为 `pi-highlights-<时间>-<随机标识>.md`。相对路径基于当前会话工作目录；支持 `~/`，自动创建父目录。文件以私有权限创建，完整写入后原子发布；已存在的文件或符号链接一律不覆盖。目标文件系统需要支持硬链接，否则会报告导出失败。
- 剪贴板使用 Pi 的官方 `copyToClipboard`，支持其系统剪贴板/OSC 52 通道。失败时会提示改用文件导出，不会声称已复制。
- 导出不会修改高亮、撤销历史、笔的模式或模型上下文，也不会请求模型。

**不静默漏导：** 如果任一高亮因历史回答被折叠、显示指纹不匹配、显示插件改写原始 Markdown，或不支持的局部布局而无法精确还原，整次导出会报错，不创建目标文件、不覆盖剪贴板。请展开对应回答并检查 `/marker status` 后重试；不会自动扩大成完整段落或偷偷跳过该片段。

## 保存与分支

- 使用 `pi.appendEntry("pi-marker:v1", ...)` 写入原会话的自定义记录，没有额外的数据库或后台服务。
- 保存消息条目 ID、内容块索引、原文/显示文本指纹、字素范围和操作日志；**不保存屏幕行列，也不重复保存整段回答**。
- 从 `getBranch()` 重放当前分支的记录。因此 `/tree` 回到标记发生之前，或从更早的位置 `/fork`，不会带入未来/其他分支的标记。
- `clear` 是可撤销操作，不会物理删除历史日志。
- `--no-session` / 内存会话不能在进程退出后保留标记，插件会提示。
- 拖动预览不写会话；松手后一次保存完整操作。局部擦除会拆分范围、重新计算文字锚点，并保留原笔的身份及其他文本块；一笔可能包含多个不连续片段。
- 写入失败时恢复原来的高亮，避免把未保存的预览当成成功。
- 不加载插件的 HTML 导出或其他会话查看器不会自动绘制这些高亮。

## 当前边界

支持普通段落、列表、引用和代码文字；已用真实 Pi 渲染器测试中文、宽字符、emoji、组合字符、跨行/跨消息拖选、滚动和窗口换行。

以下情况保守处理：

- 只标记已完成的 assistant 文本块。用户消息、工具输出、思考区、正在流式生成的回答，以及中止/失败/截断的回答不在首版范围内。
- 跨越工具/思考等区域的拖选只记录其中支持的 AI 回答文字。
- 纯空白、表格/引用边框和 U+2500–U+257F 制表符号不作为锚点。因此代码中的**纯框线图形本身**也不能单独标记；图形中的普通文字可以。
- 自适应表格、公式、Mermaid、图片、其他插件变换后的布局可能改变显示字符顺序。这时已有标记仍被保存，但**指纹不匹配就暂不绘制**；不会用模糊文本搜索猜测位置。`/marker status` 可以查看匹配数量。
- 拖选过程中窗口尺寸、消息身份、内容或已保存标记变化，会取消这一笔，提示重新选择；自动滚动不受此限制。切换模式、失去终端焦点或 reload 也会丢弃未提交的擦除预览。
- 一笔最多跨 128 个文本块，超出时拒绝并提示分段选择，不会静默截断。
- 仅提供字符单元格的实色底色，不模拟半透明纸张笔触。

## 无需请求模型的演示

在本机已经配置好开发依赖，可以直接运行：

```bash
cd /path/to/pi-marker
npm run demo
```

它会在本项目 `examples/sessions/` 下创建一个全新的示例会话，并打印加载该会话的命令。不会启动模型请求，也不会覆盖已有会话。复制打印出的命令到另一个终端即可测试。

## 开发与测试

Pi 运行插件时提供 host 模块，不需要运行时依赖。开发/测试需要 Node >=22.19 和 devDependencies：

```bash
npm install
npm run check
npm test
```

开发依赖固定为 Pi 1.6.0；未修改 Pi 核心或依赖源码。测试辅助代码使用实际安装的宿主版本，不伪装版本号。兼容性测试还覆盖冻结的渲染数组、缓存复用、损坏布局的安全拒绝，以及旧高亮的恢复、换行、导出和撤销。

测试不是只有 mock：使用真实 `TuiAltScreen`、`AssistantMessageComponent`、Markdown 渲染器、`SessionManager` 和 jiti 扩展加载器。单元/集成测试的终端使用内存替身，注入实际 SGR 鼠标序列，覆盖持久化/恢复、分支、擦除/撤销、模式切换、reload、剪贴板隔离、Unicode、ANSI、滚动、重复文本、源内容变化和 pi-tidy 呈现树。

另外提供真实打包版 CLI 的 PTY 冒烟测试（需要 POSIX、Python 3 和 `pi` 命令）：

```bash
npm run test:cli
# 同时加载本机已安装的 pi-tidy；其他机器请替换为实际入口路径
npm run test:cli -- /sun/.pi/agent/npm/node_modules/pi-tidy/src/index.ts
```

该测试使用临时配置和合成会话，禁用自动发现扩展和联网，只加载显式指定的扩展；不请求模型，不打开或修改你的真实会话/全局配置。它验证真实鼠标事件、高亮文字范围、会话落盘、Markdown 文件导出、拖动时的局部擦除预览、拆分标记的 `/reload` 恢复与撤销，以及 `/reload` 后再次导出。Linux 下以隔离 PTY 捕获 OSC 52 验证剪贴板内容，不触碰桌面剪贴板；其他平台跳过这一真实剪贴板传输检查，单元测试使用注入的替身。`PI_MARKER_TEST_TIDY_STYLE=rail|rules|off` 可切换测试布局；`PI_MARKER_TEST_THINKING=1` 可加入合成思考块。`PI_MARKER_TEST_CONTENT` 和 `PI_MARKER_TEST_EXPECT_MARKDOWN` 可指定包含 `marker target` 的合成正文及预期导出内容。`PI_MARKER_TEST_CLI` 可指定 CLI 可执行文件，`PI_MARKER_TEST_EXPECT_VERSION` 可断言实际加载的 Pi 版本，避免误测另一套安装。失败时会输出临时诊断文件路径。

### 手工验收清单

1. `/marker on` 后选择两处文字；点击别处，确认两处仍是黄色。
2. 缩窄/扩大窗口，滚动到旧回答再回来，确认位置没有漂移。
3. 尝试中文、emoji、粗体、链接和代码文字。
4. 在 `/marker on` 下重新选中一笔中间的部分，确认拖动时即恢复原样、左右仍高亮；缩小选区确认回退正确，松手后用 `/marker undo` 恢复。另试混合选区、`Esc` 取消，以及 `/marker erase` 的局部擦除。
5. `/marker off` 后选择文字，确认不会新增标记，复制行为恢复。
6. 退出并恢复同一会话，确认高亮仍在且笔默认关闭。
7. `/reload` 和 fullscreen/regular 来回切换后，确认没有重复操作或残留鼠标模式。
8. 标记部分粗体、链接和代码，使用 `/marker export highlights.md` 检查只导出了选中内容且 Markdown 完整。
9. 使用 `/marker copy` 粘贴检查；重复导出到同一文件名时，应提示未覆盖。

自动测试已通过不代表所有终端的鼠标手感都经过真人验证；本环境报告的终端是 Kitty，仍需实际拖选验收。

## 实现结构

- `src/index.ts`：扩展生命周期、零高度 TUI 桥接组件、命令与状态。
- `src/pi-adapter.ts`：集中隔离 Pi 1.5.2 / 1.6.0 的私有选区/布局接口；标记仅包装当前 renderer 实例的方法。导出时在实际宽度重绘选中块的 Markdown 实例，临时捕获 token 渲染信息，并在 `finally` 中恢复原方法描述符；绝不改全局原型或核心文件。
- `src/text-map.ts`：字素/显示列映射和 ANSI 安全背景色装饰。
- `src/store.ts`：版本化操作日志、分支重放、撤销。
- `src/markdown-export.ts`：校验完整显示字素流，裁剪 token 树，仅序列化选中内容与必要格式。
- `src/export-output.ts`：命令目标解析和不覆盖目标的原子文件导出。

高亮叠加在原文渲染之后、原生搜索/选区/浮层之前；绘制高亮不改写原始 Markdown 或渲染缓存。导出只在原宽度重建选中块的渲染缓存，不改写正文或全局渲染行为。坐标映射先限定消息 ID 和内容块，再校验原文与显示文本指纹，避免重复文字误标。
